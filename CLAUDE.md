# Friend Group Brawl: notes for Claude

Smash-style platform fighter in the browser (Three.js + Vite, plain JS, no framework). The owner is making it with 3D models of their real friend group, for personal use only, not publishing. Read README.md for controls, the cast and the model pipeline. This file covers what a new session needs in order to work on the code.

## Working with the owner

- They're new to coding and on **Windows**. Give step-by-step instructions in plain words (Command Prompt, GitHub website clicks) and avoid jargon.
- They run the game by downloading the branch ZIP (or a merged `main`), then `npm install`, then `npm run dev`, and open http://localhost:5173.
- They upload models through the GitHub website into `public/models/`, sometimes on `main` and sometimes on the work branch. **Check every branch** (`git fetch origin '+refs/heads/*:refs/remotes/origin/*'`) when they say they uploaded something, and fetch again if you don't see it yet (an upload can land while you're working).
- They're making new models of the friends to use as **outfits** (cosmetics), named like `byroncos1.glb`. Any `public/models/<id>*.glb` shows up in that friend's outfit picker by itself (`cosmetics.js`, file list from the `virtual:model-files` plugin in `vite.config.js`). Un-rigged uploads (`byroncos1.glb` was a 21 MB, 490k-triangle scan with no skeleton) need `tools/autorig.py`: rig it in place under the same name.
- They'll send voicelines later: they go in `voicelines/<character id>/`, named after the event (see `voicelines/README.md`); `src/voice.js` finds them with `import.meta.glob`, no code changes. Rename uploads to the event name (`git mv`).
- The GitHub website rejects files over 25 MB, and Meshy exports are ~25 MB (about 18 MB of that is PNG textures). Point them at the model shrinker (`npm run dev`, then http://localhost:5173/shrink.html, also linked from the menu): it re-saves the textures as JPEG in the browser and keeps the mesh, skeleton and clips byte for byte (Jacoby: 24.2 MB → 9.4 MB, looks identical).
- They merge pull requests on GitHub themselves. Don't open a PR unless they ask.
- Their usage limits are tight. They prefer big batched requests built and tested in one go, with a short summary and a screenshot at the end.
- The humor is adult stoner-comedy among friends (Draven fights with a dab pen and an empty bong). That's fine, since it's a private fictional game.

## Running and testing

- `npm run dev` starts the dev server; `npx vite build` is the quick compile check. Vite 8 needs Node 20.19+.
- There's no test suite. Verify in headless Chromium with Playwright installed in the scratchpad, **not** as a project dependency (it would make the owner's `npm install` download browsers):
  - `chromium.launch({ executablePath: '/opt/pw-browsers/chromium', headless: true, ignoreDefaultArgs: ['--headless=old'], args: ['--headless=new', '--use-gl=angle', '--use-angle=swiftshader', '--enable-unsafe-swiftshader'] })`
  - `window.brawl.game` is the live `Game`. Set `game.ended = true` to freeze the loop (it keeps rendering), then call `game.step()` yourself for deterministic frame-by-frame tests. Swap `fighter.controller = { poll: () => input }` to script inputs. Return the **full** input shape (`shield: false`, `grab: false`, `specialHeld: false` etc.): `shielding = undefined` makes the shield bubble render.
  - Matches start with whatever state the CPUs left while models loaded. Clear `hitFlash`, `invuln`, `hitstun`, `hitlag` and `move` (and `dropGrab()`) before screenshots, or a model renders as a white flash silhouette, or the first scripted press gets eaten by leftover hitlag.
  - Set `ROSTER[i].model` from `window.brawl` before clicking Fight to try a different model file. Or set up a match directly: edit `window.brawl.slots[i]` (`control`, `char`, `outfit`, `extra`), then `window.brawl.startMatch({ ...window.brawl.buildSetup(), stage: 'rushton' })`.
  - Hand close-ups: point the camera at `view.sockets.right.hand.getWorldPosition()` from ~0.4 m. Montages of small screenshots hide finger detail; zoom in before judging a grip. Hide `#results` before screenshotting the victory scene up close.
  - Victory screen: `window.brawl.showResults(rankedFighters)` builds it; `window.brawl.victory` is the `VictoryScene` (replace its `render` with a no-op and call the original yourself to step it frame by frame).
  - Scripted special tests: give each fighter a queue of inputs (`controller.poll` shifting from an array) and step; when re-placing a fighter between tests, `releaseLedge` and `dropGrab` first, and clear leftover queued inputs, or the old state leaks into the next test.
  - Editing a source file while a Playwright script runs makes Vite reload the page ("Execution context was destroyed"); just rerun.
  - Headless frame times are swiftshader numbers: only compare them to each other. `renderer.info.render.calls` (draw calls) is the number that tracks real-world speed best; a match is ~100.
  - Pose contact sheets: set `game.showHitboxes = true`, put `f.move = { name, def: f.moves[name], frame, hit: new Set() }` and call `game.render(0.05)` a few times per frame you want. Every swing should reach its hitbox on the active frames.
  - Headless rendering of the skinned model runs the sim at about half speed. **Sync tests to `game.frame`, not wall-clock waits.**
  - Override `game.updateCamera` to get close-up screenshots (two scanned models filling a 1280px frame can time out; use 960×540 or pass a longer `timeout`). Fast 4-CPU stress matches (step a few thousand frames in one `evaluate`) catch crashes, NaNs and stuck states. Effects only age in `render`, so they pile up while stepping without rendering; that's not a leak.
- Stop the dev server with `pkill -f "[v]ite --port"`. The brackets keep pkill from matching its own shell.

## Conventions

- Units are meters and seconds; frame data is in 60 fps frames. Fighters are positioned by their feet (`x`, `y`), with hurtbox `hw` × `h`.
- **Body space** for poses: +x = facing direction, +y = up, +z = the fighter's right side. Limb keys are `rArm`/`rFore`/`lArm`/`lFore`/`rThigh`/`rShin`/`lThigh`/`lShin`. A forearm value of `'mouth'` aims at the mouth. Extras: `lean`, `look`, `crouch`, `spin`, `rProp`/`lProp` (`'club'` or `'upright'`), `glow`, `rHeld`/`lHeld` (swap a prop into a hand; `null` = empty), `mount` (+ `mountX`, `mountPitch`: a prop parked at the feet that you ride, e.g. `'lambo'`).
- Move fields (full docs at the top of `moves.js`): `total`, `hitboxes[{start,end,x,y | path,r,dmg,base,growth,angle,group,prop}]` (x is relative to facing; `path: [[frame,x,y],...]` slides it along a swing; each `group` hits a victim once per move; `prop: 'right'` only counts while that hand holds its prop), `limb`, `aerial`, `landingLag`, `scripted` (the move sets velocity itself; no drift and no fall cap), `intangible: [from, to]`, `helplessAfter`, `onStart/onFrame/onLand/onHit`, `combo: {next, from}`, `available(f)` + `fallback`, `ledgeGrab`, `projectileFrame` plus `projectile` (or call `world.spawnProjectile(f, def)` from `onFrame`), `pose(frame, f)`, `onInterrupt(f, move, world)` (a hit or grab cut it short), `counter: {start, end, then}` (Byron's Krav Maga). Hitboxes can also have `when(f)` (only active while true, e.g. the car's speed tiers) and `rehit` (frames before the same group hits the same victim again, for long moves). A move that holds a frame while a button is held does `m.frame--` in `onFrame` (Hotbox, Griddy, Doomscroll). Grab moves: `grab: {start,end,x,y | path,r, reel, onCatch}` (grab box, ignores shields; `reel` frames slide a far-away catch into your hands, `onCatch(f, victim, world)`); while holding, `pummel: {frame, dmg}` or a throw: `throw: {frame, dmg, base, growth, angle}` plus `carry: [[frame,x,y],...]` (the victim's path until release). `f.pummelHeld(world, dmg)` hurts the held victim mid-move (Jacoby's burning down throw). Projectiles: clouds use `pierce`/`hitEvery`/`noKnockback`/`slow`/`unique`; thrown props use `look: 'prop'`, `vy`/`gravity` and either `pickup` (lands, owner walks over it to get it back, `returnFrames` if lost offstage, `restLift`/`restAngle` for how it lies) or nothing (bursts on landing into `burst`-colored crumbs; `roll: true` rolls along the floor instead). More projectile fields: `look: 'bubble'` (+ `text`, `color`), `look: 'puddle'` + `flat: true` (only hits people standing in it), `aim: true` (prop flies point first), `drive: true` + `ride` (vehicles: drive along floors, `gravity: 0` drives straight; `onEnd` runs when removed), and hooks `onHit(p, victim, world, result)`, `update(p, world)` (custom motion; `p.baseY` is the spawn height).
- Attack poses are `keyframes([[frame, pose], ...])`; keys inherit from the previous key and limbs slerp between keys (keep keys < ~150° apart). Line the swing up with the hitbox frames. Reference geometry: shoulder ~1.45 m, hip ~0.92 m, arm reach ~0.62 m, leg ~0.95 m, Draven's bong tip ~1.3 m from the shoulder. `pitch` flips the whole body around the waist (default uair backflip); hitbox paths for it are computed by rotating the foot around (0, 0.9).
- Hitboxes are tested as a swept capsule from last frame's position, so fast swings/lunges don't skip. Put inner hitboxes near the body so point-blank hits don't whiff.
- Input shape: `{ x, y, jump, jumpHeld, attack, special, specialHeld, grab, parry, shield, shieldPressed, downPressed, xPressed, pause }`. Keyboard grab is J / M (or shield + attack), parry K / N; gamepad triggers shield, left bumper grabs, right bumper parries. `specialHeld` is for charge moves (Draven's Hotbox holds on its frame while it's down). The CPU holds special for a random while after pressing it.
- Defense and movement: **parry** (`parry` move in `DODGES`, `parry: [1, 8]` window checked first thing in `takeHit`: returns 'parry', the attacker gets 12 frames of freeze + 44 of hitstun and `dizzy` stars, the parrier is free; projectiles reflect and change owner unless pierce/pickup/drive; grabs ignore it; the `parry` voiceline plays on success only). **Bodies push** (`Game.pushApart()` after every step: overlapping solid fighters are shoved apart, firmer on the ground, never off their platform; dodges, launched, held and ledge fighters pass through). **Air dodge** dashes ~3.3 m, refreshes on the double jump, and landing in it wavedashes (`sliding`, lower friction).
- Fighter extras: `confused` (frames with left/right swapped, Eli's brainrot), `status` (things other characters put on you, e.g. `status.brainrot` stacks), `dizzy`, `look` (cosmetics: `{ model, accessory }`), `speedMul` (run/air speed multiplier, e.g. Andrew's sugar states), `interruptMove(world)`, `power` (getter: stats × `powerBonus`), `heal(amount, world)`, `handEmpty[side]` (prop thrown), `propReturn`, `charState` (character scratch state, e.g. Jacoby's `snack` and `munchies`), `crouching` + `hurtH` (hurtbox height, 60% while crouching; crouching also takes 15% less knockback), `holding = {victim, timer, frame}` / `heldBy` (grabs; any hit on either breaks it with `releaseGrab()`). All reset on respawn. Character extras: `wear: [{ id, spot, update(item, f) }]` (things always worn, e.g. Andrew's CGM whose light follows his sugar), `preload: [urls]` (GLBs a character's props use, loaded when the match starts), `update(f, world)` (every frame, e.g. Andrew's blood sugar burn, Byron's Lambo cooldown), `victory: { pose(frame), onFrame(frame, {effects, x, y}), quote, prop: {name, x, z, yaw} }` (keep effects below ~2 m above the podium or they cover the title), `poses.*` can be objects or functions of the fighter (`base` applies in every state; `crouch` arms also apply to the `duck`), `hud(f)` (HUD status line), `cpu(f, {target, dist, dx, dy})` (CPU habits: return extra input like `{ special: true, y: -1 }`, plus `face: true` to turn toward the target, or null).
- Knockback: `kb = (base + growth * percent * 0.19 * 100/weight) * powerFactor * crouchCancel`, decaying at 25 m/s². With current tuning, KOs land around 80–200%. Throws have high growth on purpose (the owner asked that throws send farther at higher percent): back throw KOs ~100% at the ledge, ~130% from center.
- Performance: draw calls are what cost the most (WebGL on Windows pays per call). Static scenery goes through `mergeStatic()` in `stage.js` (one mesh per material; the background is ~10 meshes; it can't take material arrays, so give a textured face its own mesh); only fighters, props and platforms cast shadows (1024 map, PCF). Models are ~40k triangles with ≤2048 textures (`autorig.py`/`slim.py` do that). Reuse `toon()`, `ink()` and `mergeStatic()` for new stages; add them to `STAGES` in `stages.js`. Never add lights mid-match (three.js recompiles every shader when the light count changes): explosions are additive-blended meshes plus a CSS `.screen-flash`.
- Hands and contacts: poses can set `rHand`/`lHand` ('fist', 'relax', 'open', 'grip'), `rPalm`/`lPalm` (body-space palm direction for empty hands) and `rReach`/`lReach` (body-space point in meters; keyframes lerp these instead of slerping). Ledge hangs and grabs set reaches automatically (`reaches()` in poses.js). The victory clap reaches both palms to the same point and `separateHands()` makes them meet.
- Characters merge as `{ ...MOVES, ...DODGES, ...GRABS, ...character.moves }`. "Once per airtime" side/up special limits are applied by name in `handleActions`.
- Match the existing style: small focused modules, short comments explaining *why*, no build-time tooling beyond Vite.

## Adding a friend

1. Create `src/characters/<name>.js` (copy one of the existing ones; `eli.js`, `andrew.js` and `byron.js` show meters, charge moves, vehicles and counters), then add it to `ROSTER` in `roster.js`.
2. Set `model: 'models/<name>.glb'`. Meshy auto-rigged GLBs use `mixamorig:*` bone names; GLTFLoader strips the `:`, which `puppet.js` handles. Only a run/walk clip gets used; everything else is procedural.
   - **Un-rigged model?** Rig it yourself: `python3 -m venv /tmp/bpy && /tmp/bpy/bin/pip install bpy` (Blender 5.x as a Python module, ~400 MB, PyPI is reachable), then `/tmp/bpy/bin/python tools/autorig.py in.glb public/models/<name>.glb` (~15 s). It welds the scan's seam-split vertices (heat weights fail on the ~5000 loose pieces otherwise), decimates to 40k triangles, places Mixamo-named joints from the mesh's shape plus Mixamo proportions, skins with Blender's automatic weights on a 10x-scaled copy (at real size heat weighting silently fails for every vertex: Byron's scan did), and saves ≤2048 JPEG textures (~3.5 MB). Arms can be out (T/A-pose) or hanging a bit away from the body: it follows each arm down slice by slice past the air gap to find the hand (Eli, Andrew and Byron are all arms-down scans). The script prints `N unweighted vertices fixed by hand`; anything but ~0 means the weights failed. Check the bind pose with a `SkeletonHelper` (import `three` from `/node_modules/three/build/three.module.js` in `page.evaluate`) and pose screenshots. Needs a standing model facing glTF +Z. Don't name a scratch script `inspect.py` next to it: it shadows the stdlib module and bpy crashes on import.
   - **Rigged but heavy** (a ~25 MB Meshy export)? `tools/slim.py in.glb out.glb` keeps the rig and clips and gets it to ~3.5 MB.
3. Untextured files get a tinted clay material automatically. Models are scaled to 1.8 m and centered on the Hips bone.
4. Give them unique normals too (the owner asked for that for Draven), with keyframed poses lined up with the hitboxes.
5. Give them a `victory` animation and a `cpu` habit for each special, and list their move names in `voicelines/README.md` (plus a `voicelines/<id>/` folder).
6. Verify with close-up pose screenshots with hitboxes shown (idle, run, air, attacks, every special, ledge hang) on both the real model and the placeholder (`ROSTER[i].model = null`), scripted tests of each special, and a full 4-CPU match to the victory screen.
